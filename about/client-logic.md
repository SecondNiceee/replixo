# Клиентская логика

Здесь описана клиентская логика, обслуживающая видеозвонок: главный хук
`useMediasoup`, вспомогательные хуки, zustand-сторы, утилиты и звуки. Это
описание того, как код работает сейчас, без добавления функций.

---

## `hooks/use-mediasoup.ts` + `hooks/mediasoup/` — ядро видеосвязи, чата и доски

Главный хук, объединяющий всю работу с WebRTC через `mediasoup-client` и
сигналинг через `socket.io-client`, а также чат, статусы прочтения и совместную
доску. Вызывается на странице комнаты: `useMediasoup(roomId, displayName, create)`.

Код разбит на модули в папке `hooks/mediasoup/`, а сам `use-mediasoup.ts` —
тонкий оркестратор (join/leave, восстановление соединения, обработчики
`connect`/`connect_error`); регистрация остальных socket-событий вынесена в
`mediasoup/register-socket-listeners.ts`:

| Модуль | Назначение |
|---|---|
| `mediasoup/types.ts` | Типы (`RemotePeer`, `ChatMessage`, `ChatAttachment` и др.), константы (`SERVER_URL`, `SCREEN_QUALITY_PRESETS`, `CAMERA_ENCODINGS`), `getOrCreatePeerId`. |
| `mediasoup/reducer.ts` | Reducer состояния комнаты (peers, статус, сообщения, доска). |
| `mediasoup/use-transports.ts` | Создание send/recv-транспортов, consume, ICE restart. |
| `mediasoup/use-media-controls.ts` | Микрофон, камера, демонстрация экрана, качество, `permissionError`. |
| `mediasoup/use-chat.ts` | Отправка сообщений, загрузка вложений (`uploadChatFile`), маркеры прочтения. |
| `mediasoup/use-whiteboard.ts` | Доска (open/close/diff/snapshot) и аннотации поверх экрана. |
| `mediasoup/register-socket-listeners.ts` | Регистрация доменных socket-событий комнаты (peers, producers, чат, доска, аннотации, `kicked`). Вызывается из `join()`; обработчики `connect`/`connect_error` остаются в `use-mediasoup.ts`, т.к. запускают join/rejoin. |

> Примечание: `mediasoup-client` загружается **лениво** (`await import(...)`)
> внутри `join()`, потому что это CJS-бандл с циклическими зависимостями,
> вызывающими TDZ-сбой при статическом анализе Turbopack. Типы — локальные
> shim'ы (только compile-time).

### Состояние (reducer)

Хранится через `useReducer`. Ключевые поля:

- `status` — `idle | connecting | connected | disconnected | error`;
- `error` — текст ошибки;
- `peers` — `Map` удалённых участников (`RemotePeer`): у каждого могут быть
  `videoStream`, `audioStream`, `screenStream`, `screenAudioStream`, а также
  флаг `audioMuted` (микрофон участника на паузе);
- `localStream` — локальный поток;
- `isMicMuted`, `isCamOff`, `isScreenSharing` — состояния устройств;
- `hasMic`, `hasCam` — были ли вообще включены устройства (есть ли трек);
- `messages` — история чата (старые → новые, c ограничением в 500);
- `readMarkers` — `peerId → timestamp` последнего прочитанного участником
  сообщения (для галочек «доставлено/прочитано»);
- `whiteboardOpen`, `whiteboardSnapshot` — состояние общей доски.

При входе микрофон и камера по умолчанию выключены (`isMicMuted: true`,
`isCamOff: true`).

Помимо reducer-состояния хук хранит вне состояния: `screenQuality` (через
`useState`) и `permissionError` (`"mic" | "cam" | null`) — нефатальную ошибку
доступа, которую страница показывает баннером, не прерывая звонок.

### Подключение (`join`)

1. Создаётся пустой `MediaStream` (без запроса камеры/микрофона — их пользователь
   включает вручную).
2. Открывается socket-соединение к `SERVER_URL` (из
   `NEXT_PUBLIC_MEDIASOUP_SERVER_URL`, по умолчанию `http://localhost:3001`;
   этот же адрес возвращается как `mediaBaseUrl` для ссылок на вложения),
   транспорты — websocket с fallback на
   polling, бесконечные реконнекты с backoff (0.5–3 с).
3. По событию `connect` создаётся mediasoup `Device`, отправляется `joinRoom`
   (с флагом `create`), в ответ приходят RTP-capabilities роутера и список уже
   присутствующих участников.
4. `Device` загружается с capabilities, статус → `connected`, регистрируются
   существующие участники.
5. Создаются два транспорта — `send` и `recv` (параллельно), после чего хук
   подписывается (consume) на потоки уже присутствующих участников.

`peerId` устойчив между сессиями — хранится в `localStorage` под ключом
`replixo_peer_id`. Если та же `peerId` открывается в другой вкладке, сессия
может быть «выкинута» (kick), и хук больше не пытается переподключиться.

### Подписки на события сервера

- `peerJoined` — кто-то вошёл (даже до публикации медиа) → обновляется счётчик;
- `newProducer` — у участника появился новый поток → клиент начинает его
  потреблять (с ожиданием готовности recv-транспорта);
- `producerPaused` — участник поставил микрофон на паузу → выставляется
  `audioMuted`;
- `peerLeft` — участник вышел → удаляется из списка;
- `producerClosed` — поток закрыт (например, остановлена демонстрация экрана) →
  соответствующий тайл убирается. Есть «гонка»-защита: если поток закрылся
  раньше, чем мы успели его потребить, он помечается и не создаётся;
- `chatMessage`, `chatRead` — чат и статусы прочтения (см. ниже);
- `whiteboardOpen/Close/Change/Snapshot` — совместная доска (см. ниже).

### Управление устройствами

- **`toggleMic`** — при первом включении запрашивает доступ к микрофону
  (`getUserMedia`), добавляет трек и публикует его как producer. При повторных
  нажатиях **ставит producer на паузу** на сервере (`pauseProducer`), чтобы
  гарантированно прекратить передачу звука. Отказ в доступе выставляет
  `permissionError = "mic"`.
- **`switchMic(deviceId)`** — переключение микрофона на лету: получает новый
  трек, заменяет старый (`replaceTrack`) или публикует, если раньше не было.
- **`toggleCam`** — при первом включении запрашивает доступ к камере и публикует
  видео; далее включает/выключает трек. Отказ выставляет `permissionError = "cam"`.
- **`toggleScreenShare` / `startScreenShare` / `stopScreenShare`** —
  демонстрация экрана через `getDisplayMedia`. Видео-трек публикуется с пометкой
  `appData: { source: "screen" }` и подсказкой `contentHint = "detail"`. Системный
  аудио-трек экрана, если есть, публикуется тоже; при смене источника он
  «горячо» заменяется без обрыва видео. Нажатие «Stop sharing» в браузере
  останавливает демонстрацию. Старт/стоп озвучиваются (`playScreenShareSound`/
  `playScreenShareStopSound`).
- **`setScreenQuality(quality)`** — выбор пресета качества. Если демонстрация
  уже идёт, она тихо перезапускается с новыми параметрами.

### Камера: simulcast

Камера публикуется тремя пространственными слоями (`low/mid/high`,
`CAMERA_ENCODINGS`), чтобы SFU мог отдавать участнику с плохим каналом более
лёгкий слой вместо фриза общего потока.

### Пресеты качества экрана (`SCREEN_QUALITY_PRESETS`)

- **`auto`** — до 1920×1080@30, битрейт подстраивается под канал;
- **`720p`** — 1280×720@30, до ~2.5 Мбит/с;
- **`1080p`** — 1920×1080@30, до ~5 Мбит/с (резкий текст).

### Чат, вложения и статусы прочтения

- **`sendChatMessage(text, attachment?)`** — обрезает текст до 2000 символов,
  генерирует `id`, эмитит `chatMessage` на сервер (тот сохраняет и рассылает
  остальным) и сразу добавляет сообщение локально (оптимистично). Общий `id`
  исключает дубликаты при перезагрузке истории. Сообщение может состоять только
  из вложения (без текста).
- **`uploadChatFile(file)`** — загружает файл на mediasoup-сервер
  (`POST <SERVER_URL>/rooms/<roomId>/upload`, multipart, лимит 25 МБ) и
  возвращает метаданные вложения (`ChatAttachment`: `url`, `name`, `size`,
  `mime`). URL относительный — клиент строит абсолютную ссылку через
  `mediaBaseUrl` (адрес сервера), который хук тоже возвращает. Файлы живут
  вместе с комнатой и удаляются при её уничтожении.
- **`markChatRead(ts)`** — сообщает серверу (`chatRead`), что локальный
  пользователь прочитал чат до момента `ts`; сервер рассылает это другим, чтобы
  их сообщения сменили статус на «прочитано». Маркеры двигаются только вперёд.

### Совместная доска (tldraw)

- **`openWhiteboard` / `closeWhiteboard`** — флаг доски общий для комнаты
  (оптимистично локально + рассылка через сервер);
- **`sendWhiteboardChange(diff)`** — ретранслирует инкрементальный diff tldraw
  во время рисования;
- **`sendWhiteboardSnapshot(json)`** — сохраняет полный снимок (дебаунс на
  стороне компонента) для тех, кто подключится позже;
- **`subscribeWhiteboardChange(fn)`** — регистрирует обработчик входящих
  удалённых diff'ов, возвращает функцию отписки.

Тот же модуль (`mediasoup/use-whiteboard.ts`) отдаёт API **аннотаций поверх
демонстрации экрана**: `sendAnnotationStroke` / `sendAnnotationClear` и
подписки `subscribeAnnotationStroke` / `subscribeAnnotationClear`. Штрихи —
векторы в нормализованных координатах, эфемерные (не сохраняются на сервере);
используются компонентом `stream-annotation-canvas.tsx` (см. [`desktop.md`](./desktop.md)).

Сам компонент доски — `components/whiteboard.tsx`. Локальные правки слушаются
через `editor.store.listen({ source: "user" })` и рассылаются; удалённые diff'ы
применяются внутри `mergeRemoteChanges()` (тег `remote`), поэтому не зацикливаются.
Все статические ассеты tldraw (иконки, шрифты, переводы) раздаются с собственного
домена из `public/tldraw-assets`, чтобы не зависеть от внешнего CDN.

### Устойчивость соединения (ICE restart / recover)

- **`restartIceForTransport`** — при обрыве сетевого пути (переключение VPN,
  смена соты на телефоне) перезапускает только ICE на транспорте, не пересоздавая
  producer'ы/consumer'ы. На мобильных повторяет с backoff'ом, пока транспорт не
  вернётся в `connected`. После восстановления send-транспорта повторно
  синхронизирует paused-состояние всех producer'ов, чтобы заглушённый
  пользователь не «зазвучал» снова.
- **`recoverConnection`** — форс-восстановление при возврате вкладки на передний
  план/появлении сети: реконнектит socket и перезапускает ICE на обоих
  транспортах (с дебаунсом, чтобы частые `focus`-события не флудили сервер).

### Выход (`leave`)

Отправляет `leaveRoom`, закрывает socket, транспорты, останавливает локальные
треки и треки демонстрации, очищает потребителей, ставит статус `disconnected`.

Хук подключается при монтировании и выходит при размонтировании.

## `hooks/use-audio-devices.ts` — список микрофонов

Перечисляет доступные устройства ввода звука (`enumerateDevices`). Если метки
устройств пусты, один раз запрашивает доступ, чтобы получить нормальные имена.
Подписывается на `devicechange`, чтобы список обновлялся. Используется в
дропдауне выбора микрофона на странице комнаты.

## `hooks/use-speaking.ts` — детектор «говорит сейчас»

Анализирует аудио-поток через общий `AudioContext` и `AnalyserNode` и
возвращает булево «говорит/не говорит» с порогом и задержками, чтобы кольцо
индикатора не мерцало. Если трек выключен (mute), читается тишина. Применяется
в `VideoTile` (см. [`video-tile.md`](./video-tile.md)).

## `hooks/use-chat-button-sync.ts` и `hooks/use-room-settings-sync.ts`

Синхронизируют соответствующие zustand-сторы с БД для авторизованных
пользователей. Анонимные пользователи хранят настройки только в `localStorage`.
При входе выполняется одноразовый merge: если локальные настройки изменены
(`dirty`) — побеждают они и пушатся в БД; иначе применяются значения из БД; для
нового аккаунта БД заполняется из локальных. Дальнейшие изменения сохраняются с
дебаунсом (600 мс). API: `/api/user/chat-button-settings` и
`/api/user/room-settings`.

## Zustand-сторы

### `stores/chat-button-store.ts` — плавающая кнопка чата

Персистентные настройки кнопки (localStorage, ключ `replixo:chat-button`):

- `xRatio` / `yRatio` — позиция как доля вьюпорта (переживает ресайз);
- `visible` — показывать ли кнопку (по умолчанию `true`);
- `hotkey` — `KeyboardEvent.code` для переключения чата (по умолчанию `Tab`),
  `null` отключает;
- `dirty` — был ли стор изменён пользователем (для merge-стратегии при входе).

### `stores/room-settings-store.ts` — настройки комнаты

Персистентные настройки (ключ `replixo:room-settings`):

- `soundVolume` — общая громкость уведомлений 0..100 (по умолчанию 80);
- `dirty` — флаг изменений для синхронизации.

## Утилиты и звуки

### `lib/audio-unlock.ts` — разблокировка звука

Централизованный менеджер воспроизведения удалённого аудио. Браузеры блокируют
автозапуск звука до взаимодействия с документом. Менеджер регистрирует все
удалённые `<audio>`-элементы и пытается их проиграть, повторяет при первом жесте
пользователя и сообщает наружу, заблокирован ли звук — на основе этого
показывается баннер «Включить звук» (`EnableSoundBanner`). Также предоставляет
общий `AudioContext` для синтеза звуков. 

### `lib/sounds.ts` — звуки уведомлений

Короткие приятные сигналы, синтезируемые через Web Audio API (без аудиофайлов):
`playJoinSound`, `playLeaveSound`, `playMessageSound`, `playScreenShareSound`,
`playScreenShareStopSound`. Громкость берётся из `room-settings-store`
(`soundVolume`), при 0 звук не воспроизводится.

### `lib/display-name.ts` — имя пользователя

Хранит отображаемое имя в `localStorage` под ключом `replixo_display_name`,
значение по умолчанию — «Гость». `getDisplayName()` читает имя, `setDisplayName()`
сохраняет (пустые значения игнорируются). Используется во всех диалогах и на
странице комнаты (см. [`dialogs.md`](./dialogs.md)).

### `lib/utils.ts`

Утилита `cn()` для объединения классов Tailwind (clsx + tailwind-merge),
используется по всему интерфейсу.
